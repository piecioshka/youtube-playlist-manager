## Facts

- [2026-11-12] [project] The privacy policy is a second Vite entry, `privacy.html` (`src/privacy.tsx`), not a hash route: Google's OAuth Branding needs a plain URL that opens without signing in. Its address `https://piecioshka.github.io/youtube-playlist-manager/privacy.html` is entered in Google Auth Platform > Branding, so do not rename the file. Every HTML page needs its own entry in `build.rolldownOptions.input`.
- [2026-10-04] [project] The production build carries a CSP as `<meta http-equiv>` (GitHub Pages sets no headers), injected by `vite-plugin-csp.ts` with the hash of the inline theme script computed at build time; the dev server has no CSP. A new origin (image host, API, script) must be added there. Every e2e test fails on a CSP violation through the auto fixture `cspViolations`, but Google sign-in is stubbed in e2e, so the real popup flow has to be checked by hand on the deployed site. `src/zodConfig.ts` (`jitless`) must stay the first import of `main.tsx`: without it Zod probes `new Function` and trips the policy.
- [2026-10-04] [project] The theme preference is `system`, `light` or `dark` (`system` by default; the header toggle only stores `light` or `dark`, the opposite of the theme shown), while `data-theme` on `<html>` is always the resolved `light` or `dark`. `src/theme/themeBoot.js` (inlined into every HTML page by `vite-plugin-theme-boot.ts`, hashed by the CSP plugin) repeats the resolution and the two `theme-color` values from `src/theme/theme.ts`; change them together. Playwright runs with `colorScheme: 'dark'`, so tests start dark and switch to light themselves.
- [2026-10-04] [reference] `eslint-plugin-jsx-a11y@6.10.2` peers ESLint up to 9 but runs under ESLint 10 with `overrides: { "eslint-plugin-jsx-a11y": { "eslint": "$eslint" } }`. Its `no-redundant-roles` and `no-interactive-element-to-noninteractive-role` are off: the tables need explicit roles because they turn into grids of cards on a phone.
- [2026-10-02] [project] Playlist items carry no video duration. The playlist page fetches it after the list is shown with `videos.list?part=contentDetails&id=...` (50 ids per call, 1 quota unit each; `maxResults` cannot be combined with `id`). `usePlaylistVideos` keeps the durations in a separate map and merges them into `videos` on return, so list operations that captured an older list cannot overwrite them. The search index does not fetch durations.
- [2026-10-02] [project] A playlist item has two dates: `snippet.publishedAt` is when the video was added to the playlist, `contentDetails.videoPublishedAt` is when the video was published on YouTube. The UI shows the second, so `playlistItems.list` and `playlistItems.insert` ask for `part=snippet,contentDetails` (same quota cost; insert does not need `contentDetails` in the body). Deleted and private videos have no `videoPublishedAt`.
- [2026-10-02] [project] Video reordering runs on pointer events with `setPointerCapture` on the handle (`useVideoDrag`), not HTML5 drag and drop, which does not fire under a finger. jsdom has no `setPointerCapture` and no layout, so `PlaylistVideos.dnd.spec.tsx` stubs it, stubs `window.scrollBy` and gives every row a `getBoundingClientRect`. The handle needs `touch-action: none`, otherwise the browser scrolls and cancels the drag.
- [2026-10-02] [project] `updatePlaylist` in `api.ts` answers with `itemCount` copied from the playlist passed in (the PUT response has no `contentDetails`). The playlist list therefore keeps its own `itemCount` when a save finishes; the profile corrects it through `setItemCount` after the videos load and after every change.
- [2026-10-02] [project] `useGoogleAuth.signOut('sessionExpired')` does nothing when the token it was created for is no longer current. Without it a late 401 from a session the user already left shows "session expired" after a manual sign-out or signs out a fresh session. The guard cannot live in `App.tsx`: `react-hooks/refs` rejects a ref-reading callback passed to `createYouTubeSession` inside `useMemo`.
- [2026-10-02] [project] Specs replace YouTube with `makeFakeYouTube()` passed through `renderWithYouTube` / `youTubeWrapper` (`src/test/`). Only `session.spec.ts` and `App.spec.tsx` use `vi.mock` on `youtube/api`, because they exercise the real session; the 401 rule is tested once, in `session.spec.ts`.
- [2026-10-02] [project] The session object must stay the same for one token (`useMemo` in `App.tsx`): every data hook has it in its effect dependencies, so a new object refetches the playlist list, the channel and the videos.
- [2026-10-02] [project] With `html { scrollbar-gutter: stable }` and classic scrollbars (the Linux CI runner) `scrollWidth - clientWidth` is `-15` on a page that fits, and the gutter hides a real overflow of up to 15 px. E2E tests check horizontal overflow with `horizontalScroll()` from `e2e/fixtures.ts` (scrolls and reads `scrollX`); macOS headless has 0 px overlay scrollbars and never shows the difference.
- [2026-10-02] [project] GitHub Pages deploy (`pages.yml`) needs the repository variable `GOOGLE_CLIENT_ID` and Pages with `build_type=workflow`; both are set. The repo is private, the published site is public.
- [2026-10-02] [project] Both pages render several `role="status"` live regions: the list has two (the notice in `PlaylistsView`, the indexing status in `SearchField`), the profile has four (`PlaylistForm`, `AddVideoForm`, `UnavailableBar`, the move announcement in `PlaylistVideos`). Tests must pick one by text or scope (`within(form)`), never a bare `getByRole('status')`.
- [2026-10-02] [project] `playlistItems.update` (moving a video) needs `snippet.playlistId` and `snippet.resourceId` besides `snippet.position`, otherwise YouTube answers 400.
- [2026-10-02] [project] `PUT playlists?part=snippet,status` replaces the whole snippet and status: the current `title`, `description`, `defaultLanguage` and `privacyStatus` must be sent with every change, otherwise YouTube clears them.
- [2026-10-02] [project] OAuth Authorized JavaScript origins must match exactly. `npm run dev` takes the first free port from 3000, so CONTRIBUTING lists 3000-3002.
